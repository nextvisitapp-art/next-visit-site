# Vendored: arcads-claude-code

This folder is a copy of a third-party Claude Code / Cursor skill pack for
making AI ad creative (video and images) through the Arcads API.

- **Upstream:** https://github.com/krusemediallc/arcads-claude-code
- **Vendored at commit:** `0bfafb256cfce3ff4447d7ea1611a37f0af536be`
- **Vendored on:** 2026-07-30
- **License:** MIT (Caleb Kruse / Kruse Media LLC). See `LICENSE`, kept intact.

Everything except this file is upstream's, unmodified.

## Why it lives here

The pack is designed to be its own repo, opened as a project root. It is copied
into next-visit-site so it survives past a single Claude Code web session, since
those containers are wiped when the session ends. This folder is the durable
record, not the ideal home. See "Better long-term option" below.

## What was left out

| Left out | Why |
|---|---|
| `references/` (119 MB) | Upstream's sample influencer / product / aesthetic photos. Upstream's own `.gitignore` treats reference media as local-only, and 119 MB of sample faces does not belong in a static site repo. Recreate the folders locally and drop your own images in. |
| `.env` | Credentials. Never commit. `.env.example` is the template. |
| `MASTER_CONTEXT.md` | Per-workspace state, generated by setup from `MASTER_CONTEXT.template.md`. |
| `.claude/skills/`, `.cursor/skills/` | Generated copies. `scripts/sync-skill.sh` rebuilds them from `skills/` and `shared/skills/`. |
| `.git/` | Upstream history. Provenance is the commit SHA above. |

## Using it

The pack resolves its own paths relative to its root, so work from inside this
folder, not from the repo root:

```bash
cd tools/arcads-claude-code
./scripts/setup.sh          # prompts for the Arcads API key, writes .env
```

Setup also creates `MASTER_CONTEXT.md` and syncs the six skills into
`tools/arcads-claude-code/.claude/skills/`.

Get an API key at https://app.arcads.ai/settings/api. Publishing to Meta
additionally needs `META_ACCESS_TOKEN` and `META_AD_ACCOUNT_ID` in `.env`.

Read `README.md` for the workflow catalogue, and
`shared/skills/image-ad-prompting/OVERVIEW.md` before doing any static image-ad
work.

### Skills are not auto-discovered until setup runs

Claude Code registers skills from `.claude/skills/`. That folder is generated
and gitignored, so on a fresh clone the six skills do not exist yet. Run
`./scripts/setup.sh` (or `./scripts/sync-skill.sh` on its own) once per
container to materialise them.

### Prerequisites

`python3` and `jq` cover most of it. `ffmpeg` is needed for the caption,
Pixar-style and claymation pipelines. Caption transcription also wants
`pip install openai-whisper`, and the Meta publisher wants
`pip install -r shared/skills/meta-ad-builder/scripts/requirements.txt`.

## Updating from upstream

There is no git remote here, so this is a re-copy rather than a pull:

```bash
git clone https://github.com/krusemediallc/arcads-claude-code /tmp/arcads-upstream
# then copy everything except .git, references/, .env, MASTER_CONTEXT.md,
# .claude/skills/ and .cursor/skills/ over this folder, and update the
# commit SHA at the top of this file.
```

## Better long-term option

Upstream ships new prompt templates and workflows regularly, and a vendored copy
cannot pull them. If this pack gets real use, fork
`krusemediallc/arcads-claude-code` on GitHub, then start Claude Code sessions
against the fork directly. That keeps the pack as the project root, which is how
it expects to run, and the fork's "Sync fork" button keeps it current. This
folder can then be deleted.

## House style note

The Next Visit no-em-dashes rule applies to our own writing. Upstream's files are
full of them and are deliberately left untouched, because rewriting vendored
third-party text would make every future upstream diff unreadable.
